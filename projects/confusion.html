Facial Behavior Analysis for Confusion Recognition

An exploratory workflow for selecting facial-analysis tools, extracting action-unit features, and studying cues associated with confusion.

The question

How can observable facial behavior become a reliable, context-sensitive signal for studying confusion in learning?

From learning support to an observable research question

The internship began with a practical educational goal: investigate whether facial behavior could help a learning platform understand a student’s state, including possible confusion, distraction and affective change. A useful system would need timely, interpretable outputs rather than only a categorical emotion label. The intended deployment settings included a tablet and a web interface, so technical fit mattered alongside recognition capability.

I reviewed the Facial Action Coding System as a way to describe visible facial movements, and considered emotion frameworks for relating those observations to a learning situation. This distinction guided the work: an action unit describes movement, while confusion is an interpretation that also depends on context. A facial detector cannot by itself establish what a learner understands, so the project moved toward testing features and task-specific evidence rather than treating a generic emotion label as the answer.

Evaluating tools against the task

The midterm report documents hands-on comparisons of OpenFace 2.x and 3.0 variants, ME-Graph/OpenGraph, DeepFace, LibreFace and Py-Feat. I examined AU responsiveness, head-pose sensitivity, gaze outputs, emotion outputs and real-time behavior. Tests also considered glasses, subtle expressions and large movements. These were observations within my test setup, not a controlled benchmark ranking that can be generalized across users or hardware.

AU04 and AU07 were particularly relevant to the confusion question, but availability and apparent responsiveness differed between tools. OpenFace 2.x was useful for real-time tracking and structured output; Py-Feat and LibreFace offered broader feature pipelines with different practical limitations. I also traced dependencies, weights and dataset licensing as part of technical selection. That review informed research planning; it is not a current legal determination about every component.

Selecting datasets and constructing a traceable pipeline

I reviewed datasets against confusion labels, continuity of video, available annotations and learning context. The subsequent work used DAiSEE clips and OpenFace AU outputs for a task-specific pipeline, alongside earlier Py-Feat feature extraction experiments. Sample manifests and per-video run records make it possible to connect a chosen clip with its extracted features and processing status.

Gold and Silver groups separate held-out evaluation subjects from subjects used to construct the confusion contribution vector. This is a subject-level separation: different emotion-intensity labels can belong to the same person, so splitting only by label or clip would not prevent identity leakage. Later logs also document expanded low-confusion comparison cohorts and additional feature extraction. These preprocessing outputs show engineering progress, not completed validation of a deployable classifier.

From reliable frames to a confusion-specific representation

The updated pipeline separates frame quality from temporal localization. Quality checks require successful tracking, sufficient confidence and a near-frontal head pose. Temporal selection then identifies informative intervals rather than assuming that every frame in a clip expresses confusion equally. Intensity, change-rate and combined scores provide alternative ways to examine the difference between an expression event and a stable facial posture.

The newer configuration estimates a 17-dimensional AU contribution vector using block bootstrap. It removes an earlier synthetic AU28 dimension because that value was not a measured intensity channel. Where available, the subject’s own low-confusion clips provide an approximate individual baseline: quality-filtered median AU levels are subtracted before aggregation. This is a contextual comparison baseline, not a laboratory neutral face or proof that the lowest dataset label means an absence of confusion.

Model development, validation and revisions

The contribution vector provides an interpretable prior for targeted confusion modeling. The workspace describes knowledge-guided scoring, calibration and optional comparisons with learned baselines; scripts and local outputs document attempts to construct and inspect this representation. Subject-level stability checks, held-out Gold comparisons and possible external validation serve different purposes. I do not collapse the existence of these scripts into a claim that every proposed experiment has been completed successfully.

The iteration records also show why theory had to be checked against the dataset. An early assumption that high engagement could exclude confusion did not hold when the official labels were inspected, so that selection rule was removed. Later revisions address subject leakage, baseline handling and consistency between construction and evaluation preprocessing. These changes turned the project from a broad tool survey into a more focused investigation of how evidence for confusion should be selected, represented and tested.

Current scope and lessons

The midterm report covers the theoretical and tool-evaluation phase; newer J-drive plans, scripts, statistics and logs extend the account through dataset preparation and task-specific modeling work. The latest records include further cohort extraction, so older notes about missing comparison data cannot be treated as the current state. The work nevertheless remains exploratory: sample limitations, annotation ambiguity and individual facial variation constrain interpretation.

The strongest lesson is that a useful educational signal requires more than a detector output. Feature quality, temporal context, individual reference levels and evaluation splits all influence what can be inferred. A clinically meaningful or generally accurate confusion-recognition system is not established by these materials. This page presents the research progression and implementation decisions without publishing raw participant clips, identities or an unsupported final accuracy figure.
